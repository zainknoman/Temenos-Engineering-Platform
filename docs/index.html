What is this application?

This is currently a platform/library and integration layer rather than a finished browser application. Its job is to turn several specialist tools into one governed workflow. T24Tools is the user-facing cockpit/read-model layer; the platform supplies contracts, workflows, correlation, evidence, risk and approval boundaries.

How to use it today

The important distinction: today you use the platform through its Node.js modules and adapters. The next product step is to expose these capabilities through a proper CLI and web command center.

1. Install

git clone https://github.com/zainknoman/Temenos-Engineering-Platform.git
cd Temenos-Engineering-Platform
npm install
npm test

2. Start

npm start

The current start command loads the platform entry point. It is not yet a full HTTP/web server.

3. Integrate

Instantiate adapters and workflow modules from Node.js. Supply a project, artifacts, findings and evidence; then consume read-model/report outputs.

Important: do not treat the current package as a finished production UI. It is the platform foundation. Real provider credentials, bank repository onboarding, Temenos-Skills runtime configuration and external execution integrations still need to be wired for a real bank.

The platform is particularly suited to turning a large Transact upgrade into a repeatable migration factory.

ADC zero-downtime principle: R16 remains the active path while R25 is prepared as standby. Compatibility, data checkpoints, session/transaction safety, health checks and rollback readiness are evaluated before a human-approved external ADC drain/switch. The platform does not switch production traffic itself.

CLI Help

The tep CLI is the product entry point for deterministic project and engineering workflows. Run it from the repository with node bin/tep.js, or expose it globally for local development with npm link.

Current CLI commands
These commands are kept synchronized with the executable CLI. When a new command is added, update this tab in the same implementation change.
CommandPurposeExample
tep --helpShow CLI help.node bin/tep.js --help
tep --versionShow the platform version.node bin/tep.js --version
tep project createCreate a versioned project/workspace configuration.node bin/tep.js project create --id bank-r16-r25 --name "Bank R16 to R25" --source-release R16 --target-release R25
tep project showRead and display the current project/workspace configuration.node bin/tep.js project show
tep inventoryInspect a RepoMind export and summarize indexed files, dependencies and languages.node bin/tep.js inventory --input .\repomind.json --config .\tep.project.json
tep reportShow the project read model with project, adapter, inventory, safety and readiness surfaces.node bin/tep.js report --config .\tep\project.json
tep report --format jsonEmit the deterministic JSON read API representation for the web command center.node bin/tep.js report --format json
tep statusShow a concise project readiness/status view.node bin/tep.js status

What's next?

The foundation is now stable. The next phase should move from “platform implementation” to “usable product + real-bank validation”.

1. CLI

Create commands such as tep project create, tep inventory, tep upgrade assess, tep adc assess, tep certify and tep report.

2. Web Command Center

Build a browser UI on top of the existing read-model surfaces: project dashboard, risk list, evidence, remediation, regression, migration, ADC and certification.

3. Real adapters

Connect an actual RepoMind export, Temenos-Skills worker, PostgreSQL, queue, object storage, identity provider, SIEM and telemetry source.

4. Bank knowledge pack

Define environment topology, release versions, applications, critical channels, interfaces, batch windows, DR objectives and rollback rules.

5. Real R16→R25 pilot

Run the complete lifecycle against a non-production bank repository and produce a real upgrade assessment.

6. Production certification

Only after the pilot passes should provider credentials, external execution integrations and production governance be onboarded.

Safety model

Production remains human-controlled.
The platform can analyze, plan, correlate, simulate, verify and recommend. Production deployment, migration, ADC switching, rollback and failover remain external actions requiring explicit approval and provider configuration.
